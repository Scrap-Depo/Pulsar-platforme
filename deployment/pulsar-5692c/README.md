## Подготовленный переход

`firebase.pulsar-5692c.json` использует переходные правила этой папки: прежние права сохраняются **только для `/sessions`**, новые правила защищают `/meetings` и `/rooms`. Переход не ужесточает старые права на старые ответы. Правила генерируются из актуального канонического файла и проверенного снимка:

```sh
npm run prepare:transition
npm run check:transition
FIRESTORE_EMULATOR_HOST=127.0.0.1:8185 npm run test:transition
```

Два сценария прошли в отдельном проекте эмулятора `demo-pulsar-transition`: старый интерфейс сохраняет доступ, прежние права не открывают новые встречи, чужие личные ответы и скрытые результаты. Сборка прошла; bundle содержит проверенные Project ID/App ID и не подключается к `demo-pulsar`.

## Блокировка публикации

Functions требует Blaze. Привязка платёжного аккаунта и платный тариф пока отдельно не разрешены и не подключены. Владелец может включить Blaze в [Usage and billing](https://console.firebase.google.com/project/pulsar-5692c/usage/details). [Требование Firebase](https://firebase.google.com/docs/functions/get-started).

Blaze допускает расходы по использованию; это не фиксированная стоимость и не обещание бесплатной работы. Готовый экземпляр оплачивается также в простое.

## После подключения биллинга

1. Повторно проверить биллинг, текущий ruleset и Functions. Если правила изменились после снимка, сначала обновить и проверить переход.
2. Проверить `functions/.env.pulsar-5692c`: подготовлено `PULSAR_MIN_INSTANCES=0` для первого облачного прогона. Для согласованного сравнения с готовым экземпляром установить `1` и повторно опубликовать функцию. Изменение файла само по себе не меняет облако.
3. Опубликовать только backend с переходными правилами:

```sh
npm run check:transition
npx firebase deploy --project pulsar-5692c --config firebase.pulsar-5692c.json --only functions:pulsar,firestore:rules
```

Команда не публикует индексы и основной Hosting-сайт. Проверить фактически применённые параметры функции и возможность вызова.

4. Собрать frontend и опубликовать временный канал:

```sh
VITE_USE_EMULATORS=false npm run build
npx firebase hosting:channel:deploy pulsar-v2 --project pulsar-5692c --config firebase.pulsar-5692c.json --expires 7d
```

Preview отделяет URL интерфейса, **но использует общие Auth/Firestore проекта**. Данные разделены коллекциями и правилами. Проверить HTTPS URL, домен Auth, вход, отправку, модерацию, проектор, перезагрузку, завершение и удаление тестовой встречи. Старые `sessions` не изменять.

5. Подготовить повторно используемые аккаунты для облачной нагрузки. Локальный генератор нельзя просто переключить на облако: 101 новая регистрация за прогон конфликтует с лимитом 100/час/IP. Анонимный вход и сеть площадки проверять отдельно.
6. Сравнить первый и повторный всплески, затем готовый экземпляр; пройти пилот по `docs/EVENT-RUNBOOK.md`.

## Откат

Основной frontend при preview-публикации не заменяется. Прежние правила закрывают новую схему: перед их возвратом прекратить использование preview и согласованно вернуть совместимый backend. Данные при откате не удалять. Закрывать старые `sessions` после перехода только отдельным согласованным изменением.
