# Публикация на Vercel без Firebase Functions

Интерфейс обращается к `/api/pulsar` на том же домене. Vercel запускает
`api/pulsar.js`, который проверяет Firebase ID token (включая отзыв сессии)
и вызывает существующий `functions/service.mjs`. Firestore и Firebase Auth
остаются в проекте `pulsar-5692c`. Cloud Functions и Blaze для этого пути не нужны.
Это промежуточное размещение, а не полный перенос данных на REG.RU.

## Что подготовлено

- `vercel.json` включает HTTP-транспорт при сборке и исключает `/api` из SPA rewrite.
- Серверный ключ не импортируется во frontend. При отсутствии ключа API возвращает
  понятную ошибку настройки, а не ложное подтверждение записи.
- Локальный запуск по умолчанию продолжает работать через Firebase Functions emulator.

## Необходимые настройки перед публикацией

1. Авторизовать Vercel CLI (`npx vercel login`) и связать именно существующий проект
   `pulsar-platforme`. Не создавать новый проект и не отправлять токены в чат.
2. В серверных Environment Variables проекта задать `FIREBASE_SERVICE_ACCOUNT_JSON`
   с JSON служебного аккаунта проекта `pulsar-5692c`. Не использовать префикс `VITE_`,
   не добавлять ключ в репозиторий. Для работы нужны права на документы Firestore
   и чтение пользователей Firebase Auth; не выдавать Owner/Editor ради этого API.
3. Проверить существующие `VITE_FIREBASE_*`, особенно `VITE_FIREBASE_PROJECT_ID`.
   `VITE_USE_EMULATORS` должен быть `false`. Не задавать emulator host на Vercel.
4. Проверить актуальные облачные Firestore Rules. Новому интерфейсу нужны правила
   `meetings`, `rooms` и личных/публичных ответов. Для существующего проекта использовать
   подготовленные переходные правила из `deployment/pulsar-5692c`, сохраняющие `sessions`.
   Сначала сравнить текущие опубликованные правила с сохранённым снимком; не заменять
   чужие новые изменения старой копией. Публикация только правил не требует Cloud Functions.
5. Проверить сборку Vercel и отдельный preview; затем публиковать production.
   Настоящий результат: вход, создание встречи, подключение участника, отправка,
   отображение подтверждения и результатов, повтор без дубля, удаление тестовой встречи.

До выполнения этих пунктов опубликованный сайт нельзя считать исправленным.
Нагрузочная приёмка 100 участников на Vercel не выполнена. Тариф Hobby ограничен
личным некоммерческим использованием; проверить применимость к предполагаемым мероприятиям.

## Локальные проверки

```sh
node --test tests/http-api.test.mjs
FIRESTORE_EMULATOR_HOST=127.0.0.1:8185 FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099 node --test tests/http-api.integration.test.mjs
VITE_API_TRANSPORT=vercel npm run build
```

HTTP integration test использует настоящие локальные Auth/Firestore emulators,
проверяет токены, изоляцию владельца и запрет создания встречи анонимным участником,
сохранение ответа и повтор после закрытия без дубля. Его результат не подтверждает
настройки среды и разрешения служебного аккаунта на Vercel.

Документация: https://vercel.com/docs/functions/runtimes/node-js,
https://vercel.com/docs/environment-variables,
https://vercel.com/docs/plans/hobby.
