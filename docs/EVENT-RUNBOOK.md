# Встреча на 100 участников: проверка и запуск

Это порядок проверки, не подтверждение готовности. Немедленный показ 100 участникам пока не принят; для пилота использовать скрытый сбор и раскрытие после закрытия вопроса.

## До дня мероприятия

1. Проверить отдельный облачный стенд: вход ведущего и участников, совместимые правила, функция и frontend одного проекта. Сверить регион Firestore с регионом функции `europe-west1`.
2. Проверить лимит регистрации для внешнего IP площадки. Firebase указывает 100 новых аккаунтов/час/IP. Общая Wi-Fi-сеть, ведущие и репетиции могут исчерпать его. Заранее согласовать достаточный лимит через Firebase Console/поддержку. Другая Wi-Fi-сеть или раздача с телефона не гарантирует другой внешний IP.
3. Для облачных нагрузочных замеров использовать заранее подготовленные повторно используемые аккаунты. Локальный генератор создаёт 101 аккаунт за запуск — его нельзя просто переключить на облако. Отдельно проверить анонимную регистрацию с реальных телефонов и сеть площадки.
4. Сравнить облачные настройки `PULSAR_MIN_INSTANCES=0` и `1`. Значение `1` держит готовый экземпляр и оплачивается в простое. Параметр применяется публикацией backend, а не кнопкой в пульте.
5. Проверить первый и повторный всплески по 100 отправок. Критерии: P95 подтверждения ≤2 с, доставки ≤3 с, все 100 ответов сохранены и доставлены. Проверять личные ответы и раскрытие результатов, а не только успешный ответ API.
6. Холодный запуск подтверждать серверными журналами/метриками. Создание встречи, вход по коду и открытие вопроса уже вызывают функцию. Первый пакет внутри теста сам по себе не доказывает холодный запуск.

## Перед началом

1. Ведущий заранее открывает встречу и проверяет её название, код и настройки.
2. На отдельном экране открыть проектор. С двух телефонов проверить вход, отправку, закрытие и раскрытие тестового раунда.
3. Дать аудитории время подключиться. Счётчик подключившихся — число зарегистрированных участников, а не подтверждение присутствия всех телефонов в сети.
4. Провести тренировочный вопрос: «Насколько хорошо меня слышно?» Участники должны дождаться надписи «Ответ принят». Ведущий проверяет число ответивших.
5. Закрыть тренировочный раунд, раскрыть результаты и открыть отдельный содержательный вопрос. Тренировочные ответы останутся в своём раунде.

## При задержках и после встречи

Не просить аудиторию массово обновлять страницы или многократно нажимать отправку. Дать время подтвердить запрос; при ошибке повторить ту же попытку. При массовом сбое перейти к устному обсуждению и проверить сеть/журналы, сохранив встречу.

После завершения при необходимости выгрузить результаты. Если готовый экземпляр включали только для мероприятия, вернуть параметр в `0` отдельной публикацией после окончания. Закрытие встречи не выключает платную готовность.

Источники: [лимиты Auth](https://firebase.google.com/docs/auth/limits), [готовые экземпляры и параллельность](https://firebase.google.com/docs/functions/manage-functions), [параметры Functions](https://firebase.google.com/docs/functions/config-env).
