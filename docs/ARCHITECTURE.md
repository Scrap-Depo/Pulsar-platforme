# Схема второй версии

Новая версия изолирована от прототипа: `sessions` не читается, не мигрируется и не удаляется.

- `meetings/{id}`: владелец, редактор слайдов, версия редактора, текущий раунд. Читает только владелец.
- `joinCodes/{code}`: уникальный код -> встреча. Читает только сервер; код резервируется транзакцией.
- `meetings/{id}/members/{uid}`: участники, Firebase Auth UID стабилен в том же браузере. Имена не собираются. Максимум 100 зарегистрированных участников, не счётчик онлайн.
- `meetings/{id}/viewers/{uid}`: доступ к проектору без увеличения аудитории. Ссылка проектора использует код встречи; она даёт публичный просмотр, но не права ведущего.
- `meetings/{id}/rounds/{rid}`: неизменяемая формулировка и настройки ответа, этап, видимость, лайки, таймер. Оформление обновляется отдельно.
- `.../responses/{sha256(round:uid:slot)}`: приватный ответ. Ведущий читает все, участник только собственные по запросу `participantId == uid`.
- `.../private/{uid}`: компактный снимок максимум трёх личных ответов. Интерфейс слушает этот адресный документ вместо запроса ко всей коллекции. Обновляется атомарно при отправке и модерации; чужое чтение и перечисление запрещены. Старые раунды восстанавливают отсутствующий снимок при повторном входе.
- `.../published/{responseId}`: одобренный публичный текст/значение без UID, истории и исходного текста правки. Доступ только подключённым к встрече и только после раскрытия раунда.
- `.../likes/{responseId_uid}`: состояние лайка для конкретной версии ответа. Читает владелец или автор лайка.
- `rooms/{id}`: общая безопасная информация, текущий раунд и необязательный замороженный снимок опубликованных результатов.

Все записи выполняются через callable `pulsar` (`europe-west1`), проверяющий Firebase Auth и владельца/участие. Прямые записи клиентов запрещены. SDK токен передаётся автоматически, администраторские ключи в браузере отсутствуют.

## Конкурентность

Отправка читает встречу, раунд, участие и собственный ответ одним `getAll` в транзакции. Не изменяет общий счётчик: независимые ответы не конкурируют за один записываемый документ. Закрытие раунда меняет документ раунда и конфликтует с незавершёнными транзакциями отправки: после повторного чтения поздняя отправка отклоняется.

Документ ответа определяется раундом/UID/слотом. `requestId` подтверждает повтор той же операции даже после закрытия раунда; `revision` предотвращает перезапись устаревшей версией. Модерация проверяет версию просмотренной карточки. При изменении участником сбрасываются редакция, лайки и одобрение.

Публикация закрытого раунда записывает до 300 публичных ответов транзакцией вместе с флагом видимости. Модерация ограничена 100 карточками за операцию (до 300 записей с личными снимками). Поле `rooms.frozen` старых версий не используется клиентом; сервер очищает его при запуске и управлении вопросом. Команда `freeze` оставлена для совместимости и только очищает поле.

## Данные

Хранение до удаления ведущим, подтверждено пользователем. Завершение фиксирует данные для JSON-выгрузки. Ведущий удаляет встречу подтверждением её кода: сначала закрывается доступ и код, затем рекурсивно удаляются дочерние данные. После сбоя можно повторить удаление.

Черновики участника локальны, ключ содержит UID/встречу/раунд/слот. Очистка данных браузера или другое устройство создают другую анонимную идентичность. Это не защита от намеренной накрутки. Нельзя обещать строгую анонимность или использовать этот режим как идентифицированное голосование.
