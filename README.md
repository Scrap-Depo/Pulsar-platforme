# Пульсар

Интерактивные встречи до 100 участников: голосование, открытые ответы, шкала 1–10 и облако слов. Целевой размер аудитории не является подтверждённой производственной нагрузкой; фактические проверки и ограничения — в [docs/VALIDATION.md](docs/VALIDATION.md).

Ведущий входит по email и паролю, участники — по коду без имени. Каждый эфирный раунд хранит собственную формулировку и ответы. Публичные результаты отделены от личных ответов; запись проверяет сервер Firebase Functions.

## Установка

Node.js 22, npm; Java 21 для эмулятора Firestore.

```sh
npm ci
npm ci --prefix functions
```

## Локальный запуск без production-данных

В первом терминале:

```sh
npm run dev:emulators
```

Во втором:

```sh
VITE_USE_EMULATORS=true npm run dev -- --host 127.0.0.1 --port 5188 --strictPort
```

Открыть `http://127.0.0.1:5188/`, создать тестовый аккаунт ведущего и встречу. Для участника и проектора использовать ссылки в пульте в отдельных профилях браузера. Эмуляторы используют только `demo-pulsar`: Auth 9099, Firestore 8185, Functions 5001. Данные временные и не отправляются в production.

Ссылка с `127.0.0.1` доступна только на этом компьютере. Для реальных телефонов нужен опубликованный тестовый стенд с HTTPS; эмуляторы не следует открывать в публичную сеть.

## Работа с настроенным Firebase

Скопировать `.env.example` в `.env.local`, заполнить публичную конфигурацию Firebase, оставить `VITE_USE_EMULATORS=false`. В облаке должны быть включены Email/Password и Anonymous Authentication, опубликованы функция `pulsar` и правила из проекта. Одной публикации frontend недостаточно.

```sh
npm run dev
npm run build
```

Приложение по-прежнему собирается для Vercel как Vite SPA. Путь `/participant?code=...` предназначен для участников, `/projector?code=...` — для проектора.

## Проверки

```sh
npm test
FIRESTORE_EMULATOR_HOST=127.0.0.1:8185 npm run test:integration
npm run test:browser
npm run test:load
PULSAR_LOAD_MODE=hidden npm run test:load
npm run test:first-burst
npm run build
```

Интеграционные тесты требуют запущенного Firestore; браузерные и клиентская нагрузка — всех трёх эмуляторов. Браузерные тесты используют установленный Google Chrome и интерфейс на 5188. Нагрузочные тесты создают 100 отдельных Firebase SDK-клиентов, а не 100 реальных телефонов. Тестовые аккаунты остаются только в памяти Auth emulator до его остановки.

`test:first-burst` — первый и повторный пакеты по 100 ответов с обязательным порогом скорости. Первый пакет пока не проходит локальный порог; отчёт не называет его подтверждённым холодным запуском. Настройка готового облачного экземпляра описана в `docs/RELEASE.md`.

Старые данные прототипа `sessions` новая версия не читает и не меняет. Облачные правила требуют согласованной публикации: их нельзя применять к работающей старой версии без отдельного плана перехода.
